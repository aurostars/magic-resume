# WebDAV 安全诊断提示设计

## 背景

妙笔版本的坚果云代理已经能够访问 `https://dav.jianguoyun.com/dav/`，并能把上游 `401` 等状态转换为客户端错误。不过设置页目前只按粗粒度错误类型显示文案；当错误落入 `UNKNOWN` 时，用户只能看到“WebDAV 操作失败，请检查设置后重试”，无法判断是页面缓存、认证、目录、网络还是服务端问题。

旧客户端若仍使用已经废弃的字符串路径 envelope，当前代理会按安全约束返回 `400`。该行为必须继续 fail closed，不能为了兼容旧缓存而重新接受有路径歧义的协议。

## 目标

- 在设置页显示可复制、可检索的安全诊断码。
- 在有 HTTP 状态时显示状态码，并给出对应的下一步操作。
- 将坚果云代理 `400` 明确解释为页面版本或请求协议不兼容，提示强制刷新。
- 保持现有安全边界，不展示密码、Authorization、请求正文、上游响应正文、URL 查询参数或异常原文。
- 不改变 WebDAV 同步协议、自动建目录行为和非坚果云直连行为。

## 方案

新增纯函数，将现有 `WebDavSafeError { code, status }` 与 provider 信息转换为稳定诊断码。设置页继续使用本地化主错误文案，并在其后追加诊断信息和简短操作建议。

建议映射：

| 条件 | 诊断码 | 用户建议 |
| --- | --- | --- |
| 坚果云 + `UNKNOWN/400` | `WD-PROXY-400` | 强制刷新页面后重试 |
| `AUTH/401` | `WD-AUTH-401` | 检查登录邮箱与第三方应用密码 |
| `FORBIDDEN/403` | `WD-PERM-403` | 检查账号和目录权限 |
| `NOT_FOUND/404` | `WD-DIR-404` | 检查同步目录 |
| `DIRECTORY` | `WD-DIR-<status>` 或 `WD-DIR` | 检查目录名与创建权限 |
| `QUOTA/507` | `WD-QUOTA-507` | 清理空间或扩容 |
| `SERVER/502` | `WD-UPSTREAM-502` | 代理暂时无法连接上游，稍后重试 |
| 其他 `SERVER` | `WD-SERVER-<status>` 或 `WD-SERVER` | 稍后重试 |
| `TIMEOUT` | `WD-TIMEOUT` | 检查网络并重试 |
| `NETWORK` | `WD-NETWORK` | 检查网络并重试 |
| 其他有状态错误 | `WD-HTTP-<status>` | 按状态排查 |
| 其他无状态错误 | `WD-CLIENT-UNKNOWN` | 强制刷新；仍失败则提供诊断码 |

诊断码只由枚举错误类型、受限 HTTP 状态和是否为坚果云三个安全字段生成。

## UI 与数据流

1. 客户端请求失败后，现有逻辑仍只将 `{ code, status }` 写入瞬态 store。
2. 设置页根据当前规范化后的 WebDAV URL判断是否为坚果云。
3. 设置页通过纯函数计算诊断码。
4. 错误提示展示：主错误文案、`诊断码：...`；HTTP 状态仅在合法整数状态存在时展示。
5. 错误信息不持久化，不增加日志或遥测，不收集凭据。

示例：

```text
请求格式与当前服务版本不兼容，请强制刷新页面后重试。
诊断码：WD-PROXY-400 · HTTP 400
```

## 测试

- 单元测试覆盖所有诊断码映射和非法状态回退。
- UI 合约测试覆盖坚果云 `400`、认证 `401`、上游 `502`、无状态 `UNKNOWN` 的中文展示。
- 安全测试断言提示中不出现用户名、密码、Authorization、请求正文或服务器响应正文。
- 回归运行 `test:webdav`、相关妙笔生产契约及妙笔构建。

## 发布与验证

按现有妙笔发布流程构建并发布新 GitHub Pages release、API FaaS 和 Web FaaS，健康检查通过后再切换固定页面。发布后用无凭据的畸形请求验证 `400`，并确认页面展示新的安全诊断码。真实坚果云凭据仍只由用户在浏览器中输入。
