# 默认进入简历工作台设计

## 背景

当前所有部署访问根地址 `/` 时，会根据浏览器语言跳转到 `/$locale`，因此首先展示营销导览页。用户需要点击“立即开始”后，才能进入 `/app/dashboard/resumes`。

目标是让妙笔、GitHub Pages 和其他部署访问根地址时都直接进入“我的简历”工作台，同时保留导览页的显式访问能力。

## 范围

### 包含

- 将根路由 `/` 的默认重定向目标改为 `/app/dashboard/resumes`。
- 保留 `/zh`、`/en` 等现有导览页及其内容。
- 增加路由合约测试，防止默认入口回退到导览页。
- 发布后验证妙笔固定入口直接落到 `#/app/dashboard/resumes`。

### 不包含

- 删除或重新设计营销导览页。
- 修改“我的简历”页面、新建简历、导入简历或 WebDAV 同步行为。
- 根据用户是否已有简历动态选择入口。
- 修改导航栏中主动访问导览页或工作台的现有链接。

## 方案

修改 `src/routes/index.tsx` 的根路由 `beforeLoad`：不再读取首选语言并跳转到 `/$locale`，而是直接重定向到 `/app/dashboard/resumes`。

路由流程变为：

```text
访问 /
  → 根路由 beforeLoad
  → /app/dashboard/resumes
```

用户显式访问 `/zh`、`/en` 等地址时，仍按原有路由渲染导览页。

## 选择理由

与在页面挂载后调用导航相比，路由级重定向不会先渲染导览页，因此没有闪屏，也不会增加组件生命周期或 hydration 风险。

与分别修改妙笔、GitHub Pages等部署入口相比，统一修改根路由只有一个行为来源，各部署保持一致，维护成本最低。

## 数据与状态

该变更不读取或修改简历、本地存储、WebDAV 配置及语言设置。现有简历工作台继续负责空状态、新建简历、导入简历和设置入口。

## 错误处理

根路由只使用 TanStack Router 的静态重定向能力，不引入异步操作或新的错误分支。若工作台路由无法加载，继续由现有应用错误边界处理。

## 测试

采用测试驱动方式增加最小路由合约测试：

- 根路由将 `/` 重定向至 `/app/dashboard/resumes`。
- 根路由不再将 `/` 重定向至 `/$locale`。
- 妙笔仍使用 Hash History，最终地址为 `#/app/dashboard/resumes`。
- 显式语言路由仍然存在，导览页未被删除。

发布后在妙笔固定入口执行浏览器验收：

- 首次打开不显示导览页。
- 最终地址为 `#/app/dashboard/resumes`。
- “我的简历”空状态或已有简历列表正常显示。
- 页面无新增运行时错误，静态资源无 404。

## 风险与回退

- 新用户不再先看到产品介绍，但工作台已有明确的新建和导入入口，符合本次产品目标。
- 已保存的 `/zh`、`/en` 链接仍可使用。
- 如需回退，只需恢复根路由原有的语言重定向，不影响其他路由和用户数据。
